# Guilduo v0.6.0-beta.8 — Web App・人間レビュー・公開ガイドの改善

Guilduoは、人と外部AI AgentがQuestを共有し、引き継ぎ・成果物確認・フィードバックを進めるワークプラットフォームです。前回のアプリRelease `v0.6.0-beta.7` 以降の改善を、このソースReleaseにまとめました。

**このGitHub Releaseは、本番再配備なしで公開するソーススナップショットです。引き続き公開βであり、安定版GAや一般顧客の受入完了を意味しません。** Web Appのアプリ版は `0.6.0-beta.8`、ホスト拡張はそれぞれ別の版番号で管理します。

## 主な変更 / Highlights

### Guilduo / Relay Forgeを使いやすく

- CommandのQuest参照、未完了の依存関係によるブロック表示、履歴表示を修正し、画面間の情報を揃えました。
- モバイルのヘッダー・下部ナビゲーション・操作領域・画面切り替え時のスクロールを改善しました。
- 新規Appwriteアカウントのワークスペース初期化、再接続時の表示、Settingsの権限案内と不要なMCP接続の削除を改善しました。
- 初期ワークスペース取得の集約・並列化と保存処理の改善を進めました。配備時には旧画面が参照するハッシュ付きアセットの保持と検査を追加し、開いたままの画面の読み込みを保護します。

### Appwrite・MCPと人間レビュー

- Agentから人へ確認を依頼する `request_human_review` と、回答を取得する `list_human_requests` を追加しました。人はWeb Appで確認し、テキストのフィードバック、変更不要、保留・再開を返せます。
- **人の確認完了、Agent Handoffの受理、元Questの完了は別の状態です。** 確認リンクを開くことや人の回答だけで、元Questを自動完了しません。
- Agent登録、OAuth接続、ClientとAgentのリンク、最初の操作を段階ごとに案内し、権限不足や読取専用の理由を分かりやすくしました。Agent登録だけでモデルを起動することはありません。
- Appwriteのアカウント・ユーザー状態と、WorkerのREST/MCP・Agent接続管理の境界を維持し、接続復旧とOAuth状態の永続化を改善しました。通常のMCP接続先は [https://mcp.guilduo.com/mcp](https://mcp.guilduo.com/mcp) です。

### 日英Docs・Solutions・SEO/AEO

- 日本語・英語それぞれ18記事の公開Docsを整備しました。MCP、各AIホスト、Quest、引き継ぎ、人間レビューの導入・操作手順を、検索と関連リンクから辿れます。
- 「MCPタスク管理」「AI Agentの引き継ぎと人間レビュー」の日英Solutionsを公開しました。LPには操作デモと開始手順を追加し、今回の更新では利用前提と短い試用手順を先に示しています。デモ・例示画面は顧客事例や最新の実機試験結果として扱いません。
- 静的HTML、canonical、日英の相互リンク、本文に対応する構造化データ、44 URLのsitemap、robots、`llms.txt`を整備しました。未知のDocs/Solutionsページは実HTTP 404を返し、Web AppのHTMLは `noindex,follow` としています。
- 検索とAIによる回答抽出を助ける説明・出典を改善しました。索引反映、順位、AI引用、流入増加は別途評価する結果であり、本Releaseで達成を保証しません。

### 明示的な同意後のGA4・Appクリック計測

- 公開LP・Docs・Solutionsで、新しい同意案内への明示的な同意後にのみ、運営者向けのページ閲覧・Appクリック計測とGA4を有効にします。以前の匿名計測への同意をGoogleへの同意として流用しません。
- ページ・言語・流入元は限定した分類で扱い、GA4には正規化した公開ページURLを送ります。生のクエリやUTM、検索語、アカウントID、Quest内容を計測へ渡しません。GA4は仮名化されたブラウザ識別子を使用します。
- 広告向け同意・パーソナライズ、Google Signals、自動拡張計測、アカウント連結を無効にしています。同意撤回で計測を停止し、待機イベントと対象Cookieを消去します。
- 10月12日の公開記録では、同意前の送信なし、同意後の `page_view` / `app_cta_click` のGA4 realtime受信、撤回後の再ナビゲーションでの送信停止を確認しています。**これは運営者の検証イベントです。登録・Activation計測や実利用者数・集客目標の達成を示すものではありません。**

### ホスト拡張は別Release

- OpenAI / ChatGPT、Codex、Grok Bot、Muse Code向けの候補パッケージは、別の [guilduo-next-hosts v0.6.0-beta.12 Release](https://github.com/ELRdn/Guilduo/releases/tag/guilduo-next-hosts-v0.6.0-beta.12) で配布しています。アプリbeta.8と混同しないでください。
- 共通Workflow Skillは、読み取り・dry-run・確認・実行・レビュー返却を案内します。Codexの補助hookは信頼確認と明示bindingが必要です。OpenAI審査用パッケージにはhookを含めません。
- 配布確認と各ホストの受入は別です。OpenAIの審査・公開承認、Grokの実ホスト受入、MuseのOAuth・モデル・Human往復、Codexの信頼済みhook実行などには残件があります。日付付きの限定的なCodex受入や合成fixtureを、今回の全ホスト・最新実機QAとして扱いません。
- 導入は [日本語Docs](https://guilduo.com/docs/) / [English Docs](https://guilduo.com/docs/en/) と [ホスト別の受入範囲](https://github.com/ELRdn/Guilduo/blob/479b21113d5cd9590c552fed5f0b1de2631be2ed/docs/acceptance/guilduo-next-hosts-publication.md) を参照してください。

## Releaseと本番の境界 / Release safety

10月12日のSEO/GA4更新は [PR #67](https://github.com/ELRdn/Guilduo/pull/67) に記録しています。確認対象headは `6166f2c`、そのベースの公開mainは `479b211` です。本番Siteはソース `4c9fcf3` の配備が完了しており、Workerには稼働中の実装を保持したtelemetry差分を適用済みです。これらの配備とGitHubのソースReleaseは別に管理します。

**本番Workerには、公開ソースへ未統合の直接配備変更が残っています。GitHubのSource code ZIP/TARを本番Workerと完全一致するものとして扱わず、稼働中ソースとの整合が完了するまで汎用Worker配備は控えてください。** 公開ソースでの全面上書きは、稼働中の修正を失うおそれがあります。

タグworkflowからSite/Workerの自動本番配備を分離しました。版番号・main履歴・版別ノートを照合し、型・テスト・ビルドと公開ページの検証後にソースReleaseを作成します。配備が必要な場合は既存のmanual deploy workflowを別途使用し、Workerについては上記のソース整合を先に満たす必要があります。本Releaseの公開では、Site/Workerの再配備やD1 migrationを行いません。

検証根拠は、各日付・対象ソースの公開記録です。今回のSite配備には型・テスト・ビルド、Docs/Solutions、キャッシュ・アセット保持の検査記録があり、本番のHTTP検査とデスクトップブラウザ確認も記録しています。旧画面と現行Appの認証済み読取起動も確認されています。過去の受入、合成fixture、HTTP検査、画面幅のエミュレーションを、今回の物理端末・全ホスト・全アカウントの受入へ読み替えません。

課金の公開や外部Providerの一般提供を開始するReleaseではありません。公開βの制限とホストごとの残件は継続します。

## English summary

**v0.6.0-beta.8 is a GitHub source snapshot published without redeploying production. Guilduo remains a public beta; this is neither stable GA nor completed general-customer acceptance.** It summarizes app improvements since `v0.6.0-beta.7`; host extensions retain their own versions.

- **Web App:** Improved Command Quest references, dependency blocking and history, mobile navigation and touch targets, new Appwrite workspace initialization, reconnection and Settings. Startup reads and saves were improved, with retained hashed assets and deployment checks protecting already-open app shells.
- **Human review:** Agents can request a human check and retrieve saved feedback through MCP. People can answer, defer and resume in the Web App. Human review, Handoff acceptance and source Quest completion remain separate. OAuth connection and Agent linking are distinct steps; registering an Agent does not run a model.
- **Docs and discovery:** Published 18 articles per language and two bilingual use cases, with an LP demo and getting-started guidance. Static HTML, canonical/language links, visible-content structured data, a 44-URL sitemap, genuine missing-page 404s and App `noindex,follow` improve discovery. Illustrative demos are not customer evidence; indexing, rankings and AI citations require later results.
- **Consented analytics:** Public page views and App CTA clicks reach operator telemetry and GA4 only after explicit consent to the new notice. Tracking uses sanitized canonical pages and finite categories, without raw query/UTM values, account IDs or Quest content. GA4 uses pseudonymous browser identifiers. Advertising features, Signals, enhanced measurement and account linkage are disabled; withdrawal stops collection and clears pending events and relevant cookies. October 12 realtime reception was operator verification traffic, not signup/activation tracking or proof of real-user growth.
- **Separate host packages:** The [next-hosts beta.12 prerelease](https://github.com/ELRdn/Guilduo/releases/tag/guilduo-next-hosts-v0.6.0-beta.12) distributes OpenAI/ChatGPT, Codex, Grok Bot and Muse Code candidates. Distribution is not host-directory approval or full native acceptance. OpenAI review, Grok native testing, Muse OAuth/model/Human acceptance and trusted Codex hook execution retain separate gates.

The October 12 Site deployment used `4c9fcf3`; production Worker telemetry was updated while preserving its active implementation. **The live Worker still includes direct-deployment changes absent from public source. Source ZIP/TAR archives are not an exact production Worker bundle. Avoid generic Worker deployment until that source has been reconciled, or active fixes could be overwritten.** The tag workflow now checks package version, main ancestry and release notes, then publishes the source release after type, test, build and public-page gates. Production deployment is separate, using the existing manual workflows under those safety conditions. This source Release performs no Site/Worker redeployment or D1 migration.

Dated CI, production HTTP checks and desktop browser records establish their stated scopes only. Historical acceptance, synthetic fixtures and viewport emulation are not fresh physical-device or comprehensive customer acceptance. This release does not launch billing or generally enable external Provider integrations.
