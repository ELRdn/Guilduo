# REA競合リサーチの取り込み計画 — All for ADHD（2026-10-25）

出典: [ELRdn/todo-app-REA](https://github.com/ELRdn/todo-app-REA)（opencode + REA 6.4.0。Asana / Toggl / Habitica / Tiimo / Structured の比較と、合成案「Spine」）。
モック: [2026-10-25-rea-adoption-mock.html](2026-10-25-rea-adoption-mock.html)。

ラベル: **[Evidence]** このリポジトリかリサーチの観察。**[Research-INF]** リサーチ側の推論（LPと公式画像が主で、アプリ内挙動は未観察）。**[Inference]** この計画での判断。未検証。

## 1. 前提

- リサーチの証拠は、ほとんどがマーケティングページと公式画像である。完了アニメーション、空き時間タップ、ドラッグなどの挙動は [Research-INF] で、実アプリでの検証はない。この計画では「参考になる仮説」として扱い、ドッグフーディングで確かめる。
- 2026-10-18 brief（[2026-10-18-all-for-adhd-brief.md](2026-10-18-all-for-adhd-brief.md)）の P1〜P10 は維持する。ただし P2（操作数の上限）は下の決定 1 で緩める。

## 2. オーナー決定（2026-10-25 壁打ち）

1. ホームは「今」（自分のQuest 1件）と「今日のタイムライン」を1画面にする。P2 の上限（Desktop 15 / Mobile 12）は外し、ドッグフーディング後に決め直す。
2. Quest の種類を画面で分けない（Habitica の4列は採らない）。繰り返しは Quest の設定として扱う。
3. 優先は (a) 空き時間の提案、(b) Quest ごとの絵文字、(c) 書くだけで予定化。
4. データモデルと API は、必要なら大きく変えてよい。移行計画を付ける。
5. 見た目は DESIGN.md と Bloom を維持する。取り入れるのは、完了で閉じるリングと紙吹雪、パステルの絵文字円。詳細は §4.7（モック後の深掘りで決定）。
6. 空き時間の提案元は「受け箱から収まるもの」「休む／何もしない」「Agent が提案」「Agent に任せる」の4つ。
7. 絵文字は自動で付け、自分でも Agent でも変えられる。
8. 書き出しはルールで解析し、大きいものは Agent がステップに分ける。

## 4. 機能設計

### 4.1 ホーム「今」＝今のQuest＋今日のタイムライン

- **Desktop（≥ 900px）**: 2カラム。左（約 400px）に今のカード（主操作は1つ）、右に今日のタイムライン。受け箱は「予定」に残す。
- ホームのタイムラインは **Structured 型の等間隔の行**にする（§4.7）。行は「時刻 | 絵文字カプセル（縦線でつながる）| カード」。所要時間はカプセルの高さで示す（40〜96px、`24 + 分 × 0.6`）。現在時刻は行と行のあいだに線で入れ、作業中の行はカプセルを経過時間の扇形で塗る。時間比例のグリッドは「予定」タブ（日・週）に残す。
- **Mobile**: 今のカードを上に置き、その下にタイムラインを続ける。タイムラインは「このあと」の範囲（現在時刻の1時間前から）を最初に見せ、上に「それより前 n件」の折りたたみを置く。
- タイムラインのブロックでできる操作は、完了リングとタップで詳細を開くことの2つ。ドラッグでの移動は「予定」にだけ置く。
- 作業中のQuestは常に今のカードに出す（P8 維持）。タイムラインでは同じブロックを経過時間で塗る（既存の挙動）。
- 「予定」タブは残す（週・月・受け箱）。ホームと重なるのは日表示だけで、日表示の初期値は今日以外の日にする。[Inference]

### 4.2 空き時間の提案カード

- 対象は15分以上の空き（今は30分以上）で、現在時刻より後のもの。行と行のあいだに破線のカプセルと「{分} 空いています」を置く。提案（最大3つ）を開いて出すのは次の空きだけにし、それ以降の空きは「提案を見る」で開く（同じ提案が並ぶのを避ける）。
- 提案の順番:
  1. **Agent が提案したQuest**（§5 の `proposal` があり、その空きに収まるもの）。Agent の名前を添える。
  2. **受け箱から収まるもの**: 自分担当、未定、`estimatedMinutes` が 1 以上で空き以下。締め切りが近い順、次に古い順。1件だけ。
  3. **休む**: 常に最後に出す。押すと「休憩」ブロックを置く。休憩はQuestにしない（ローカル表示のみ）。[Inference]
- 「Agent に任せる」は、提案した受け箱のQuestの「⋯」から選べるようにする。既存のリレーで Agent に渡す。
- 選んだら、その空きの開始時刻と目安で `scheduledDate` と `scheduledTime` を入れる。確認は出さず、5秒の「元に戻す」を出す（P5）。
- 目安のないQuestは提案に出さない。これで目安の入力を促す（実データでは目安があるのは31件中4件）。[Evidence/Inference]

### 4.3 絵文字

- 作成時、タイトルのキーワード辞書（9言語、`emoji.ts`、数百語）で1つ決める。決まらなければ空欄にして、Quest の色の点だけを出す。AIは使わない。
- 表示: 36px のパステルの円（Quest の色を 20〜30% にした背景）の中に置く。今のカード、タイムラインのブロック、やることの行で使う。
- 変更: 詳細シートの円をタップすると、候補（辞書の上位8件と最近使ったもの）と「なし」が出る。
- 色だけで意味を伝えない（a11y）。絵文字は `aria-hidden` にし、タイトルが読み上げの対象になる。
- OSで絵文字の見た目が違う問題 [Research] は受け入れる。ブランドの要素ではなく、覚えるための手がかりとして使う。

### 4.4 書くだけで予定化

- 全画面共通の書き出し欄に、ルールのパーサ `parseCapture(text, locale, today)` を置く。
  - 日付: 今日／明日／あさって／曜日／`10/26`、各言語の同義語。
  - 時刻: `15時`／`15:00`／`3pm`／`午後3時`。
  - 目安: `30分`／`1時間`／`1h30`／`30m`。
  - タグ: `#仕事`。
  - 残りはタイトル。
- 入力欄の下に、読み取った結果を1行で出す（例: `明日 15:00–15:30 · 目安30分 · #health`）。「今日やる」トグルより日付指定を優先する。
- 読めない部分はそのままタイトルに残す。入力を失わせない（WCAG 3.3.7）。
- 「大きい」の判定: 目安が60分を超える、または「〜する」が2つ以上ある。この場合、追加後のトーストに「Agent にステップに分けてもらう」を出す。押すと既存のリレーで Agent に「ステップに分けて、各ステップに目安と絵文字を付ける」を頼む。Agent は MCP の `create_quest`（`parentQuestId`）で子Questを作る。新しい仕組みは要らない。

### 4.5 繰り返し

- 詳細シートに「繰り返し」チップ（なし／毎日／平日／毎週／毎月）を足す。値は既存の `Quest.repeat` に入れる。
- 完了の挙動は既存どおり（記録を残して active に戻る）。完了すると、タイムラインのブロックはその日のあいだ完了表示のまま残す。
- 「毎日のタスクは毎日今日に出す」既存ルールを、`weekdays` と `weekly` にも広げる（その日に当たるときだけ）。

### 4.6 完了の表現

- チェックの円が 120ms で塗られ、行が薄くなり（opacity .55）、紙吹雪が出る。この3つを1つの完了表現にする。XP は同じトーストに1行で添える（ゲーム要素がオンのとき）。
- 完了したブロックはタイムラインから消さない（Spine の不変条件5）。薄くして、タイトルに取り消し線を入れる（§4.7）。

### 4.7 見た目のトーン（2026-10-25 モック後の決定）

| 項目 | 決定 | DESIGN.md への影響 |
|---|---|---|
| 日付の見出し | 48px・weight 300・`letter-spacing -0.02em`、曜日は16pxで小さく添える。Mobile は40px | Display より大きく細い指定が増える。`interaction-lab/DESIGN.md` の All for ADHD 節に差分として書く（DESIGN.md 本体の型は変えない） |
| ブロックの塗り | タスク色30%の塗り＋左3pxの色帯（モックの濃さ、今の予定画面と同じ） | なし |
| ホームのタイムライン | 等間隔の行。長さはカプセルの高さ | All for ADHD 節の「予定」の記述にホームの行を足す |
| 完了 | 薄く（opacity .55）＋取り消し線。紙吹雪とリングは今のまま | 完了の表現を1文追記 |
| 絵文字の円 | 今のサイズ（行36〜40px、今のカード56px） | 新しいコンポーネントとして追記 |
| 背景 | グラデーション（Bloom の wash）をやめ、平坦な地にする | All for ADHD 節の Bloom の記述（放射グラデーション）を書き換える |
| 配色 | **Spine に決定（2026-10-25、Bloom を置き換え）**。以下は試用時の記録。Spine パレット（REA 06-synthesis §3.1–3.2：地 `#FBFAF7`、主 `#2F5D50`、今 `#E2725B`、タスク色は低彩度6色、Agent は indigo）を試用中。モックで Bloom（平坦）と切り替えて比べる | 採用するなら DESIGN.md のパレット変更になるため、別途オーナー決定を取る |

Guilduo のブランド色（DESIGN.md §1.1）は役割を決めたサブカラーとして混ぜる（2026-10-25 オーナー：ライトは満足、ダークの緑が不満）。ライトは Spine のまま。ダークは土台をブランド色に置き換える：地 = Night Surface `#0F1418`、選択 = Forge Teal `#13352F`、文字 = Ivory `#E7E3DA`、主ボタン = Antique Gold `#B89A5E`（文字は Night Surface）。Spine のミント `#8FBFB0` は使わない。

Spine を試用するときの調整: `ink-3 #8E8B95` は `#FBFAF7` の上でコントラストが約3.3:1と足りないため、モックでは補助文字を `#6F6C76`（約5:1）にしている。ダークのタスク色は Spine に定義がないため、ライトの値を明るくした仮の値を使う。

## 5. 契約の変更（移行計画）

| 変更 | 内容 | 互換 |
|---|---|---|
| `Quest.icon: string` | 絵文字1つ（書記素1つ、最大16 UTF-16単位）。既定は `""` | 追加のみ。既存のQuestは `""` |
| `Quest.iconSource: "auto" \| "user" \| "agent" \| ""` | 誰が付けたか。Agent の上書きは `user` 以外のときだけ | 追加のみ |
| `Quest.proposal: { agentId, date, time, minutes, note, createdAt } \| null` | Agent が置いた「この時間にどうですか」。人が受けると `scheduledDate` と `scheduledTime` に移し、`null` に戻す | 追加のみ |
| openapi `Quest` schema | 上の3フィールドを足す。PATCH で更新できる | additive |
| MCP | `create_quest` / `update_quest` に `icon` を足す。新しいツール `propose_quest_slot(questId, date, time, minutes, note)` を作る（プレビュー → 実行の2段、既存の書き込み方針に合わせる） | 新規ツール |
| Relay Forge | `icon` をタイトルの前に表示する。`proposal` は詳細に「Agent の提案」として読み取り専用で出す | 表示のみ |

- サーバーの検証: `icon` は書記素1つ。`proposal.minutes` は 5〜1440。`agentId` は登録済みの Agent に限る。
- 移行: 既存データは触らない（読み込み時に既定値を補う）。一括で自動付与はしない。新規作成と編集のときだけ付ける。
- 名前は互換に関わる識別子なので、QuestForge 系の名前はそのまま使う（AGENTS.md）。

## 7. 検証

- **計測スクリプト**（`tools/measure-ui-load.mts`）: P2 は外すが、数値は記録する。比較の基準は 2026-10-18 の値。
- **ドッグフーディングで見る数字**:
  - 目安のあるQuestの割合（今は 4/31）。

## 8. 未決事項

- 等間隔の行で、所要時間をカプセルの高さだけで伝えられるか。ドッグフーディングで確かめ、伝わらなければ時間比例に戻す。
- 休憩ブロックをQuestとして記録するかどうか。今はローカル表示だけにしている。
- `proposal` を1件に限るか、複数持てるようにするか。今は1件。
- 週次レビューは3つの数字だけ入れた。Toggl の記録時間を使った振り返りはまだ。
