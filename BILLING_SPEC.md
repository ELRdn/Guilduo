# Guilduo billing specification

Updated: 2026-10-06. **Local implementation candidate; public paid sale is unavailable until product configuration and real acceptance are approved.** This specification does not establish legal, Stripe Live, Jev quality or operational validation.

## Approved behavior

- Free permits **two registered Agents**. Count `active` and `disabled`, exclude `archived`. Disabling an Agent does not free a registration slot. Count Agents, not OAuth/MCP connections.
- Pro registration is unlimited. Connection membership, request size and rate limits remain separate safety limits.
- Existing/downgraded Free accounts keep every record. The owner selects the two usable Agents; until selection, over-limit Agent execution stops. Viewing, selecting and archiving remain available. Upgrade restores eligibility without recreating records.
- Enforce limits at the common Web/REST/MCP boundary and atomically in D1 registration, including concurrent creation and reactivation. Shared MCP restricts the acting Agent, preserving other allowed members.
- Ordinary MCP CRUD, Quest and Handoff operations consume **zero AI Credits**. Only approved Guilduo intelligence/compute consumes Credits. Auto top-up is OFF; top-up sales are excluded.
- First paid AI capability: text-only finite-choice suggestions for an eligible Agent and next action through **official TypeSafe Jev**, `POST https://api.typesafe.ai/v1/systemone`, using native `fetch`. No Luna/OpenRouter implementation, images, free-text generation, automatic Agent start or automatic Quest completion.
- Pin an actually available official model version; do not use `latest`. Verify candidates, probabilities/confidence, permissions and Quest revision before explicit application via existing assignment/Handoff. At most 255 choices, shown explicitly. Low confidence, invalid results and timeouts return to manual selection.

## Money, entitlements and ledger

Stripe Checkout/Customer Portal is the initial integration. Appwrite identity is mapped server-side to Customer/Subscription. Raw-body signature verification, event deduplication and Stripe re-query/reconciliation drive entitlements; redirects never grant Pro. Never store card details in Guilduo. Test and Live identities, events, balances and credentials stay separated.

D1 records grant, reserve, commit, return, expiry and adjustment with reason/source and idempotency key. Balance and ledger update atomically. Payment-cycle grants and the referrer's first eligible paid-invoice reward occur once. Unknown downstream outcomes remain pending reconciliation; do not blindly repeat paid processing or refund the reservation.

Accept payment success/renewal/failure, scheduled cancellation, expiry, refund, dispute and plan change according to the approved product decision. Validate replay, inversion, parallel delivery, duplicate grant/spend, insufficient balance and reconciliation. The referrer receives free Credits after the first eligible payment; signup, zero-price invoice, self-referral and duplicate payment events do not qualify. Refund/reversal and already-spent reward treatment must be decided before enabling the feature.

## Configuration and public-sale gate

- `BILLING_ENABLED=false` (default), `BILLING_MODE=test` (default), `JEV_ENABLED=false` (default). Missing switches never start paid processing.
- `BILLING_CONFIG` is backend-validated approved product JSON, **not a place for secrets**. Test configurations are synthetic and cannot authorize a public paid launch.
- Worker-only Jev variables include `JEV_MODEL`, verified tariff values, `JEV_DATA_POLICY_APPROVED=false`, `JEV_EVALUATION_BUDGET_USD=1`, `JEV_BUDGET_SCOPE=evaluation` and empty `JEV_COMMERCIAL_CONFIG`. Evaluation retains its persistent lifetime USD1 ceiling. The local candidate supports separately approved commercial Test/Live periods of at most 32 days, immutable ceilings and no overlaps; Live refuses evaluation scope. Worst-case reservations and uncertain outcomes remain held against the original period. No automatic ceiling increase/reset is permitted. The USD5 amount and October 6–November 5 interval are adopted; customer disclosure and capacity remain BM-01 acceptance items; Pro unlimited refers only to Agent registration.
- Worker Secrets: `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `TYPESAFE_API_KEY`, `BILLING_ADMIN_TOKEN`. Browser runtime and Git never contain these or the server billing configuration. Stripe keys must match mode.
- Signed candidate evidence binds the exact approved billing JSON and Jev variable JSON to the candidate SHA. Generated and active Worker variables must match before Site activation. A manifest for billing-off deployment cannot pass the paid Release gate.
- Only after BM-01–05 real evidence, public Go, Live setup and permitted small-payment/refund acceptance may public sale be enabled. Backend/UI implementation completion is not this approval.
